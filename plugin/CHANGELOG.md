# 変更履歴

## 1.6.0 — 2026-09-26

日本語校正の 2 スキルを、最近のモデル（Claude Fable 5.1 世代）の日本語の癖に合わせて更新。
語の誤りや不自然な敬語は減った一方で、構成と強調の型に癖が移っている点を反映した。

- `japanese-business-writing` — A-15〜A-18、B-8、C-11 を追加。A-6 と A-8 を拡張
  - A-15 「〜ではなく、〜」の対比で強調しない（否定した側を踏み台にしない）
  - A-16 「〜することで、〜が可能になります」の因果連結をやめる。「〜することができます」は「〜できます」
  - A-17 「鍵」「ポイント」「重要」「土台」「両輪」で重要さだけを告げない
  - A-18 「〜していきます」「〜してまいります」で締めない
  - B-8 「ご安心ください」「ぜひ」で読み手の気持ちを先回りしない
  - C-11 カタカナのビジネス語の置換表
  - A-6 文頭の論理接続詞を毎文に置かない。A-8 「〜において」「〜に関して」の格助詞の漢語化
  - D 絵文字と記号アイコン、「ラベル：説明」の箇条書き、末尾の「まとめ」「次のステップ」の自動追加を禁止
  - 手順 13・14 に、対比・因果連結・予告・呼びかけ・進行形の締め・自動追加節の検索を追加
- `japanese-business-writing/references/phrase-table.md` — 15〜20 を追加（対比、因果連結、予告と比喩、
  進行形と呼びかけの締め、カタカナ語、格助詞の漢語化）
- `japanese-business-writing/references/document-structure.md` — 19・20 を追加
  （資料の型にない節を足さない、「ラベル：説明」の箇条書きは表にする）
- `japanese-business-writing/scripts/patterns.json` — 10 分類を追加（対比の強調、因果の連結、
  重要さの予告と比喩、進行形の締め、呼びかけの締め、格助詞の漢語化、カタカナ語、会話調の残留、装飾、
  自動で付く節）。15 分類から 25 分類へ。`scan_expressions.py` は `node_modules`・`dist`・`build` を走査対象から除外
- `japanese-rewrite` — 「人らしさを装わない」の節を追加。「人が書いたように」の指示を「ですね」「なんです」の
  口語で満たさない。装飾の規則を「Markdown 禁止」から「元文にない装飾を足さない」へ改め、見出しや表を持つ
  資料の構造は保つ。厳守ルールと納品前チェックに対比・因果連結・予告・締めの項目を追加
- `plugin/docs/導入手順.md` — 既にインストール済みの環境での更新手順を追加

## 1.5.0 — 2026-09-01

  LibreOffice を前提とした記述を削除

## 1.4.0 — 2026-09-01

文書の種類ごとの文末の使い分けと、状態の書き方を追加。

  - 16 技術リファレンスは体言止めで揃える。A-2 の「体言止めの連打をやめる」は読ませる文章の規則で、

## 1.3.0 — 2026-09-01

README や手順書を書くときの型を追加した。実際のレビューで受けた指摘を反映している。

- `japanese-business-writing` — B-7 を追加。道具や AI を主語にして判断を断定しない。
  AI は作業の代行者であり責任者ではない、という関係を文面で崩さない
- `japanese-business-writing/references/document-structure.md` — 11〜15 を追加
  - 11 README・手順書は、読み手と書き手の立場を先に決める
  - 12 見出しは対象を名詞で示す（問いかけ、動詞句、目的語のない動詞を使わない）
  - 13 表に入る情報を本文で繰り返さない（条件の箇条書きより列を足す）
  - 14 言い換えの説明を足さない（「あとから追える」は「追跡可能」）
  - 15 内部の判断理由を見出しにしない（採用しなかった選択肢は備考へ）

## 1.2.0 — 2026-09-01

レビュー側のスキルを 2 件足し、要件書向けのチェックリストを追加した。スキルは 7 件から 9 件になった。

- `basic-design-review` — 新規。要件側と設計側の双方向照合、記述の欠落（画面・API・データ・権限・
  エラー処理・バッチ）、非機能 6 区分、運用と保守と障害対応、未決の確定化、用語と識別子と数値と
  図表の整合。観点表と良い例・悪い例を `references/` に置いた
- `ai-design-prompt-review` — 新規。AI 向けの指示を 10 項目で点検する。書いていないことと
  書きすぎの両方を見る。プロンプトインジェクションの型 6 つと、プロンプト側・運用側の対策を
  `references/injection-cases.md` にまとめた。実際に動く攻撃文字列は載せない
- `deliverable-review-register` — `references/requirement-quality-checklist.md` を追加。
  曖昧語、未定義語、主語の欠落、検証できない要件、機能と非機能の混在、正常・異常・境界の不足、
  ID と根拠と受入条件の不足、要件間の矛盾、決定と提案と未決の混同、トレーサビリティの不足。
  各項目に誤検知を避ける条件を書いた

## 1.1.0 — 2026-09-01

提出前の機械検査を追加した。スクリプトは claude-kit の `just` から呼ぶ。

- `requirements-xlsx` — `xlsx_qa.py` を追加。数式エラー、外部リンク、非表示のシート・行・列、
  名前定義、入力規則、シート間参照、表示形式の揺れ、コメントの付いていない未決セルを検査し、
  JSON と Markdown を出す。SKILL.md の §10 を書き直し、実行できる環境の切り分けを入れた
- `pptx-house-style` — `pptx_qa.py` と `pdf_qa.py` を追加。文字切れ、フォント混在、図形の重なり、
  スライド番号、タイトル重複、出典の有無、PDF のページ数・構造・文字抽出可否を検査する。
  SKILL.md の §8 を書き直し、`pptx_audit.py`（修正前後の比較）との役割を分けた
- `qa_report.py` — 検査結果の書き出しを両スキルに同じ内容で置いた。スキル単体でも動かせるようにするため、
  共有モジュールにはしていない
- PDF は PowerPoint から書き出す方針を明記した。LibreOffice は日本語フォントが置き換わるため、
  文字切れの確認には使わない

## 1.0.0 — 2026-09-01

要件定義フェーズの案件で蓄積した指摘を、案件から切り離してスキル化した初版。

- `japanese-business-writing` — 既存の日本語ビジネス文書スキルに、案件で受けた指摘19項目のうち
  未収録だった10項目を統合した（「同等」への統一、目的語を言い切る、列挙の括弧化、見出しの体言止め、
  中身のないリード文、隅付き括弧での範囲表示、造語の禁止、効果の誇張、二択に見せない、
  申し送り事項の根拠）。置換表を `references/phrase-table.md`、構成ルールを
  `references/document-structure.md` へ分離した。納品前の機械走査 `scan_expressions.py` を追加
- `japanese-rewrite` — 固有名詞を除去して移植
- `emphasis-first-drafting` — 質問ツールの記述を一般化して移植
- `deck-visual-design` — 顧客名を除去し、`pptx-house-style` との役割分担を明記して移植
- `pptx-house-style` — 顧客名を除去。本文中のコードを `scripts/` の4本へ切り出し、
  実測値の記入例を `references/measured-spec-example.md` に分離
- `requirements-xlsx` — 新規。要件定義Excelの記入ルール、採番規約、未決セルとコメント運用。
  `xlsx_open_items.py` で「コメントの付いていない未決セル」を検出する
- `deliverable-review-register` — 新規。議事録と成果物の双方向照合による指摘台帳の作り方。
  要件定義資料向けの4区分と、見積書向けの重要度S〜Dの2つの型を収録
