# Emphasis-First Drafting

## なぜ必要か

LLMが生成する資料の典型的な失敗は「フラット化」である。網羅性は高いが、5つの論点がすべて同じ見出しレベル・同じ分量で並び、読み手はどこを読めばいいか分からない。人間が書く資料は、書き手の中に「これが一番言いたいこと」があり、それが分量・配置・語調に自然に反映される。この暗黙の重みづけが、指示のない生成では失われる。

対策は簡単で、**書き始める前に重みを聞く**こと。ただし聞き方が重要で、漠然と「どんな資料にしますか」と聞いても有用な答えは返ってこない。

## 手順

### 1. 材料を読む

議事録、既存資料、参照ファイルに目を通してから質問する。文脈を持たない質問は答えづらく、ユーザーの時間を無駄にする。

### 2. 重みを確認する（必須）

選択式の質問ツール（Cowork なら AskUserQuestion）を使う。散文で質問を並べない。

**必ず聞くこと：主目的の順位づけ**

その資料が果たしうる目的を3〜4個並べて順位をつけてもらう。ここが設計の骨格になる。

```
質問: 「この資料の主目的（最も重きを置くもの）は?」
選択肢例: 「相手に判断してもらう（判断軸の提示）」
          「費用・期間のインパクト提示」
          「技術的アプローチの説明」
          「スケジュール全体像の共有」
```

単一選択ではなく順位づけにするのは、2位以下が「載せるが軽く扱う」項目を決めるため。1位だけ分かっても、残りを削るのか薄く残すのかが決まらない。

**題材に応じて聞くこと（1回あたり2〜3問まで）**

- **分量・形式** — 1ページ／2ページ／それ以上。分量は重みづけの最大の制約であり、これが決まらないと削る判断ができない。
- **数値の踏み込み度** — 相対表現のみ／レンジまで／確定値まで。相手に判断を迫る資料ほど、数字の粒度が信頼性を左右する。
- **選択肢の提示形式** — 2択／3択（中間案あり）／対象ごとに個別。
- **推奨スタンス** — 明示的にリコメンドする／中立に並べる／仮説として控えめに。これは資料のトーン全体を決める。中立指定なら「当社としては〜を推奨」という文を一切書かない。

質問は**1回で3問、必要なら追加でもう1回**が上限。それ以上は聞き取り自体が作業の邪魔になる。

### 3. 回答を設計に翻訳する

聞いただけで反映しないのが最悪のパターン。以下のように機械的に対応させる。

| 回答 | 資料への反映 |
|---|---|
| 主目的1位 | 冒頭セクションにする。「本日ご相談したいこと」等で最初に明示。最大の紙面を割く |
| 主目的2位 | 1位を支える根拠として配置。1位の直後か、独立セクションで中程度の分量 |
| 主目的3位以下 | 1〜2行の補足、脚注、または「別途ご提示します」と明記して切り出す |
| 分量2ページ | セクション6個程度が上限。各セクションの行数を先に割り振ってから書く |
| 数値=レンジまで | 「60〜100人日」のように幅で示し、「※概算であり変動する」注記を必ず添える |
| 中立スタンス | 選択肢表の列を等幅にし、メリット／留意点を各案に同数書く。推奨マークを付けない |
| リコメンド型 | 推奨案を色・太字で目立たせ、「推奨理由」を独立させる |

### 4. 濃淡を可視化する

作成後、自分の出力を見て確認する。

- 1位の目的に割いた分量が最大か
- すべてのセクションが同じ長さになっていないか（なっていればフラット化している）
- 読み手が最初の10行で「何を求められているか」を理解できるか
- 3位以下の項目が本文を占領していないか

### 5. 完成物と一緒に、何を軽く扱ったかを伝える

「〜を1位としたため、〇〇は補足に留めました」と一言添える。ユーザーが重みづけの妥当性を検証できる。

## やらないこと

- 材料を読まずに質問する
- 4問以上を一度に聞く
- 「どんな感じにしますか?」のような答えづらい抽象的な質問
- 回答を聞いたのに全項目を均等に書く
- 中立指定なのに推奨を滲ませる、リコメンド指定なのに両論併記で終わる
- ユーザーが既に詳細な指示を出している場合に、改めて聞き直す（その指示が答えである）

## 適用外

議事録の文字起こし、要約、翻訳、コード生成、単純なデータ整形。これらは重みづけの設計余地がないか、元データの構造がそのまま答えになる。
