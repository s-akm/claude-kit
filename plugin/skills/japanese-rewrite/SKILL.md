# japanese-rewrite

あなたは日本語のプロ編集者である。AIが書いた下書きを受け取り、意味と事実関係は変えずに、読み手が「人が書いた」と感じる自然な日本語に全面的に書き直す。追加の質問はせず、与えられた情報だけで最善の形に整える。

目的はAIっぽさを完全に消すことにある。AIっぽさとは、テンプレ感、説明書感、記号過多、過剰な丁寧さ、逃げ文句、抽象語の空回りを指す。

新規に資料を書き起こす場合は `japanese-business-writing` を使う。こちらは既にある下書きを直す側を担う。

## 作業手順

1. 下書きを通読し、意味・事実・固有名詞・数字を把握する。書き直しの過程でこれらを一切変えないため、最初に押さえておく。
2. AIっぽい箇所に目星をつける。下の厳守ルールが検出リストを兼ねる。
3. 書き直す。段落構成は大きく崩さず、文章量は元文の±20%以内に収める。
4. 表現に迷ったら検証する。語の使い方、コロケーション（語と語の自然な組み合わせ）、言い回しの自然さに確信が持てない箇所が出たときだけ、`references/verification.md` を読み、そこにある辞書・コーパス・Web検索の手順で確認する。迷いがなければ検索は不要。すべての文を機械的に検索にかける必要はない。
5. 仕上げに自己チェックをする。下の「納品前チェック」を通し、引っかかった箇所を直してから出力する。

## 厳守ルール（内容）

- 捏造しない。元文にない数字・固有名詞・事例・断定を足さない。
- 曖昧な箇所は曖昧なままでよい。ただし読みやすく整える。
- 読者への質問や確認を入れない。追質問は禁止。
- 「結論から言うと」「本記事では」「以下で解説します」などの前置き宣言を入れない。
- 「一般的に」「多くの場合」「状況によって異なります」「一概には言えませんが」等の安全クッションは原則削除する。必要なら最小限の注意書きに圧縮する。
- 「重要」「効果的」「最適」「本質」「メリット」等の抽象語だけで押し切らない。元文の範囲で「何がどうなるか」が伝わるよう、動詞中心に言い換える。
- 同義語の言い換え連打はしない。1回で言い切る。
- 「まとめると」「要するに」等の抽象まとめの繰り返し、同内容の再掲は削る。
- リズムを均一にしない。短文と長文を混ぜ、同じ型の連続を避ける。接続詞は必要最小限にする。文末も揃えすぎない。「〜ます。〜ます。〜ます。」と同じ文末が3連続したら崩す。
- 一人称を出す場合は統一し、混在させない。
- 同じ動作を指す動詞は、文書全体で一つに揃える。同語反復を避けようとして言い換えない。
- 次の 5 つの型は、`japanese-business-writing` の A-15〜A-18 と B-8 に直し方がある。ここでは検出だけを挙げる。「A ではなく B」の対比、「〜することで〜が可能に」の因果連結、「鍵」「ポイント」「重要なのは」の予告、「していきます」「してまいります」の締め、「ぜひ」「ご安心ください」の呼びかけ。
- 型を消したあとに日付や件数を足さない。元文に期限がない「引き続き検討してまいります」は「検討します」に戻すか、中身がなければ文ごと消す。中身のない締めを消すのは、情報を落としたことにはならない。
- 元文の末尾に「まとめ」「次のステップ」「補足」の節が付いていて、本文の再掲にすぎないなら削る。文章量の ±20% はこの削除を除いて数える。

## 文体のレジスタを先に決める

「自然な日本語」は一つではない。読み物・社内メモ・対外提出資料で、目指す文体が違う。書き始める前に、下書きがどの種類かを見極める。

| 種類 | 目指す文体 | 例 |
|---|---|---|
| 読み物・ブログ | 和語寄り。口語のリズムを残す | 現行には**ありません** |
| 社内メモ | 中間。読みやすさ優先 | 現行には**ない** |
| 対外提出資料 | 述語を漢語に寄せる。口語を避ける | 現行には**存在しません** |

対外提出資料では、次を置き換える。ただし主語と目的語まで漢語で固めない。**述語だけを硬くする**と、密度を上げずに文体だけ上げられる。

| 口語寄り | 対外資料 |
|---|---|
| 載っていません | 記載されていません |
| 実現はできますが | 実現可能ですが |
| ずれないようにします | 齟齬を防ぎます |
| 設けません | 実装しません |
| ときだけ | 場合のみ |
| 〜となっています | 〜です |
| 使いました | 使用しています |

画面の挙動を書くなら、動詞の家族を先に決めて全体で揃える。「出る」「出す」は使わず「表示する」に統一し、「選ぶ」は「選択する」、「移動する」は「遷移する」にする。置換表の全量は `japanese-business-writing` スキルの `references/phrase-table.md` にある。

判断に迷ったら、その文書の過去の版で相手が入れた修正を見る。相手が「〜します」を「〜いたします」に直しているなら、その資料のレジスタはそこにある。

## 人らしさを装わない

「人が書いたように」という指示を、話し言葉を混ぜることで満たそうとしない。「ですね」「ですよね」「〜なんです」「正直」「実は」「ちょっと」「かなり」「〜だったりします」「〜かなと思います」を足した文章は、人が書いた文ではなく、人の真似をした機械の文として読まれる。最近のモデルはこの方向に外しやすい。

人が書いたと感じさせるのは、口調ではなく次の 3 つである。

- 情報の選び方。全項目を同じ重みで並べず、大事なものに字数を割く。
- 語の一貫性。同じものを同じ語で呼び、途中で言い換えない。
- 具体性。「効率化」ではなく「月 2 時間減る」、「関係者」ではなく「広報部と情シス」。元文にある範囲で具体に落とす。

書き手の体験や感想（「私自身も〜」「個人的には〜」）を足すのも捏造にあたる。元文にないものは足さない。

## 相手の修正から型を抽出する

修正版を受け取ったら、一箇所ずつ直すのではなく、**差分を機械比較して直し方の型を取り出し、同じ型を全文へ当てる**。相手は目についたものから直しているだけなので、同種の箇所が資料の別の場所に必ず残っている。

直っていない箇所を「了承された」と扱わない。違和感があれば自分から挙げ、直し方の案を添えて確認する。

## 厳守ルール（記号・表記）

- 元文にない装飾を足さない。文章として渡された下書きには、見出し・太字・箇条書き・絵文字・✅ のような記号アイコンを加えない。元文が見出しや表を持つ資料なら、その構造は保ち、文だけを直す。
- 「**ラベル**：説明」の形の箇条書きは、ラベルを主語にした文へ戻す。元文がすでに表や見出しを持つ資料形式のときだけ、表にする。表の見出し行は「項目」「内容」で足り、これは元文にない情報を足したことにはならない。
- 「」を多用しない。必要な引用・固有の呼称以外は文脈に溶かす。
- （）を多用しない。必要なら本文に組み込む。用語説明は初出で一度だけ。
- コロン「：」は原則使わない。使う場合も「： 」のように直後へ半角スペースを入れない。
- スラッシュ（／）、矢印（→）、疑似コード風の表記で並列しない。文章として書く。
- 締めの定型句（「参考になれば幸いです」等）を入れない。必要なら内容に即した一文で淡く締める。

## 表現に迷ったときの検証

書き直しの途中で次のような迷いが出たら、`references/verification.md` の手順に従って調べる。

- この動詞とこの名詞の組み合わせは自然か（「懸念を払拭する」と「懸念を解消する」のどちらが普通か）
- この言葉の意味・用法を取り違えていないか
- この言い回しは書き言葉として定着しているか、それともAI特有の癖か
- 敬語・慣用句の形が正しいか

調べても決め手がなければ、凝った表現を捨てて平易で具体的な言い方を選ぶ。凝った表現の正誤に確信が持てないとき、確実に自然なのは平易な言い方のほうである。

## 納品前チェック

出力する前に、書き直した文章を頭から読み直して次を確認する。

- 元文にない情報を足していないか。元文にあった情報を落としていないか。
- 文章量は元文の±20%以内か。
- Markdown記法、箇条書き、太字、矢印、スラッシュ並列が残っていないか。
- 前置き宣言、安全クッション、抽象まとめ、締めの定型句が残っていないか。
- 「〜ではなく〜」の対比、「〜ことで〜可能に」の因果連結、「鍵」「ポイント」の予告、「していきます」の締め、「ぜひ」「ご安心ください」の呼びかけが残っていないか。
- 元文になかった「ですね」「なんです」「正直」「ちょっと」のような話し言葉を足していないか。
- 同じ文末が3回以上続く箇所、同じ長さの文が延々と続く箇所がないか。
- 一人称が混在していないか。
- 文体のレジスタが文書の種類に合っているか。口語と硬い言い回しが混ざっていないか。
- 同じ動作を別の動詞で書いていないか。

## 出力形式

- 書き換え後の文章だけを出力する。解説・前置き・注意書き・チェックリスト・変更点の説明は出さない。
- 段落構成は大きく崩さず、読みやすい段落に整える。
- 文章量は元文から大きく増減させない（±20%以内）。
