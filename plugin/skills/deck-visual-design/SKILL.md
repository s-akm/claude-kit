# Deck Visual Design（落ち着いた企業スライド）

pptx skill と併用する。pptx skill が「ファイルをどう組むか」を担い、こちらは「どう見せるか」を担う。テンプレートのマスター・レイアウト・フッターは必ず継承し、その上に本文を載せる。

顧客の既存デッキに合わせる作業は `pptx-house-style` を使う。**既存ページが1枚でもあるなら、このスキルの数値ではなく実測値を優先する。** こちらは参照できる既存ページが無いときの初期値である。

## AIが作るスライドがダサくなる理由

避けるべきものを名指しする。生成物にこれらが出たら作り直す。

- **色ベタ塗りのカード**を何枚も並べる（濃い青地に白抜き文字のブロックが3つ横並び、など）
- **装飾ストライプ**、見出し脇の色帯、意味のない図形
- **矢印記号（→ ▶ ⇒）** を本文に直置きし、しかも原色で目立たせる
- **アクセントカラーの多用**。1枚に3色も4色も差し色が入る
- **過剰な太字**。文章全体が太字だと強弱が消える
- **中身のない角丸ボックス**の乱用
- 全項目が同じ大きさ・同じ色で並ぶ**フラットな一覧**

良いスライドは、白地・広い余白・細い罫線・1〜2色の抑えた差し色でできている。情報の階層は、色数ではなく**文字サイズと余白**で作る。

## デザイントークン

16:9（13.333in × 7.5in = 12192000 × 6858000 EMU）を前提とする。

```
# 色（テンプレートの基調に合わせて BASE を差し替える。他はほぼ共通で使える）
BASE = "0B3B70"   # 基調色。見出し・数字・罫線の強い方。テンプレートのブランド色に合わせる
INK  = "1A1A1A"   # 本文。真っ黒(000000)にしない
SUB  = "6B7280"   # 補足・二次情報のグレー
LINE = "DCE3EA"   # 細い罫線。うっすら見える程度
WASH = "F4F7FA"   # 淡いパネル地。ベタ塗りの代わりにこれを使う
SRC  = "9AA5B1"   # 出典・注記のさらに薄いグレー
ACC  = "0A7EA4"   # 差し色。青緑寄りにして「デフォルト青」を避ける。1枚に1色まで
WARN = "B3541E"   # 「大／注意」を示す時だけのくすんだテラコッタ

# 余白（本文領域）
CX, CY, CW = 719983, 1080838, 10752052   # 左端・上端(タイトル下)・本文幅
FOOT = 6426100                            # フッター上端。本文はここより上で終える

FONT = "游ゴシック"   # 日本語資料は原則これで全系統統一（後述）
```

配色の原則：**基調色＋グレー階調（INK/SUB/SRC/LINE/WASH）が土台。差し色（ACC/WARN）は1枚に1色、1〜2箇所まで。** 差し色を「なんとなく賑やかしで」使わない。強調の意味があるときだけ。

## 文字サイズの段階

サイズで階層を作る。太字とグレーを併用して、色に頼らない。

```
大きな数字・キーメッセージ   2800–3000 (b)
スライド内の小見出し         1900–2000 (b, BASE)
項目タイトル                 1400–1550 (b, INK/BASE)
リード（タイトル下の一文）    1250      (SUB)
本文                         1100–1200 (INK)
補足・キャプション            1000–1100 (SUB)
出典・注記                    850–950   (SRC)
```

## レイアウトの型（この4つで大半が組める）

1. **リード＋3カラム**：タイトル下に主張を1文（リード）。下に3つの観点を、番号＋細罫線＋見出し＋本文で。カードのベタ塗りはしない。区切りは罫線と余白で作る。
2. **数字ブロック**：4つ以下の指標を横並び。各々「細い縦アクセント罫線＋大きな数字＋ラベル＋補足＋薄い出典」。数字を主役にする。
3. **比較テーブル**：ヘッダ行だけ基調色地に白文字。データ行は白と WASH の交互（ゼブラ）。枠線は LINE。強調したい値だけ色と太字。
4. **淡色インセット**：結論・帰結・注意を、WASH 地の囲みにグレー文字で置く。矢印もアクセント色も使わない。「囲ってあること」自体が弱い強調になる。

## 2色構成のデザインシステム（参考テンプレートがあるとき）

顧客テンプレートが無く、参考にできる既製デッキがある場合は、その**テーマ色を実測してから2色に落とす**。
既製デッキの色数をそのまま持ち込むと散らかる。濃色1色＋差し色1色＋グレー階調に絞る。

```bash
python3 - <<'EOS'
import zipfile, re, collections
z = zipfile.ZipFile("参考.pptx")
c = collections.Counter()
for n in z.namelist():
    if re.match(r"ppt/(slides|slideLayouts|slideMasters)/\w+\d+\.xml$", n):
        c.update(re.findall(r'srgbClr val="([0-9A-Fa-f]{6})"', z.read(n).decode("utf-8", "ignore")))
print(c.most_common(14))
EOS
```

出現頻度の上位から、濃色（地）・差し色（面）・差し色（文字に使える濃さ）・淡い面・
さらに淡い地・罫線を割り当てる。参考例（HubSpot「データ分析」テンプレートから起こした値）。

```
DEEP   = "001B2F"   # 表紙・章扉・表ヘッダの地
BASE   = "33475B"   # 見出し
INK    = "2A3540"   # 本文
SUB    = "616F80"   # 補足
SAGE   = "8BB7B4"   # 差し色（面）
SAGE_D = "5E8F8C"   # 差し色（文字・罫線に使える濃さ）
SAGE_L = "C4DBD3"   # 淡い面
WASH   = "F1F6F5"   # さらに淡い地
LINE   = "D8E2E4"   # 罫線
```

赤・オレンジ系の差し色は、脆弱性・漏えい・事故を扱う資料では選ばない。内容と釣り合わず軽く見える。

### 白地ミニマルだけだと地味に見える

余白と細罫線だけで組むと、整ってはいるが「デザインされていない」と受け取られる。
次の4つを混ぜると、色数を増やさずに印象が変わる。

1. **章扉は全面ベタ**。部番号を 80〜90pt の暗い差し色（地より少し明るい濃色）で大きく置き、
   見出しは 30pt 白、リードは淡い差し色。
2. **表のヘッダ行は濃色ベタに白文字**。データ行は白と淡色の交互（ゼブラ）。枠線は引かず、行の区切りだけ 0.5pt。
3. **数字ひとつだけのページ**を要所に挟む。90pt 超の数字と一文だけ。話すときに間を作れる。
4. **割合は横棒**で描く。数字を並べるより差が見える。地の棒を淡色、値の棒を差し色、
   基準を下回るものだけ別色にする。


### 表の1行だけを強調する

「この行だけが変わった」を示したい表では、その行の地を淡い差し色にし、
値の列を差し色の濃い方で太字にする。行を増やして矢印を足すより静かで、目は確実にそこへ行く。
**同じ表の中で強調は1行まで。** 図と表を併記しているなら、図の対応する要素も同じ色にする。
表で「開発」を強調したのに帯図では別の色、という食い違いは必ず指摘される。

### 数値カードに前年の値を添える

「増えた」「減った」を数字だけで言うと伝わらない。カードの下に2本の横棒を置く。
上に淡い色で前年、下に濃い色で当年、上の棒の右に「2024　76%」のように年と値。
前年の値が無い指標にも1本だけ棒を入れて、カードの形を揃える。

凡例はカード群の下に1行（「淡い棒が2024年、濃い棒が2025年」）。
カードごとに凡例を置かない。



### 表と図の粒度が違うときは注記する

同じページに表と図を置くと、項目の分け方がずれることがある。
表は「企画・要件定義」を1行、図は「企画」と「要件定義」の2つ、という形。
**どちらかに揃えるのが本筋だが、揃えられないなら図の見出しに注記を添える。**
「工程ごとの所要期間（上表の「企画・要件定義」は、下図では2つに分けています）」。

### 凡例は適用範囲まで書く

「淡い棒が前年、濃い棒が今年」という凡例は、前年の値を持たない指標にも掛かって見える。
**どれに適用されるかを凡例に書く。**「前年との比較があるのは左端と右端の2指標のみ」。

## 実装：XMLを直接組む

python-pptx はテキストボックスの自動高さやフォント指定で扱いづらい。テンプレートを unzip し、スライド XML を文字列生成して差し込むのが確実。罫線・淡背景・セル書式・フォント統一のヘルパは `pptx-house-style/scripts/deckkit.py` にある。要点は次のとおり。

- テキストボックス、塗り／枠付き図形、罫線、プレースホルダ見出し、リード文、出典注記の6種類でほぼ足りる
- 各段落は行間を明示する（例 140000 = 140%）
- 色は必ずトークンを使い、直値を散らさない


### 大きな数字と単位は別の枠にする

「45」と「%」を1つの枠に入れると、推定描画高さが数字の級数（96pt など）で計算され、
下の見出しと重なったと判定される。また日本語フォントの実測幅は 0.55em 見積もりより広く、
「45」が2行に折り返す事故が起きる。**数字と単位を別枠にし、どちらも `word_wrap` を切る。**
枠幅は `文字数 × 級数 × 0.72 / 72 + 0.16in` を目安にする。

### テキスト枠の高さには下駄を履かせる

検査スクリプトの推定式（行間 1.40 ＋ 段落後 3pt）を上回る高さを枠に与えないと、
「文字切れ」として大量に警告が出る。生成側は行間 1.45 ＋ 0.09in で見積もる。
折り返し判定の幅も 0.07in ほど辛めに取る。

### 3ファイル構成にする

`data.py`（文言とノート）、`build_pptx.py`（ページの組み立て）、`deckkit.py`（体裁ヘルパ）に分ける。
文言だけの修正依頼が `data.py` の書き換えで済み、体裁を触らずに回せる。

## フォント統一（日本語）

テンプレートは英数と日本語で別フォントが当たっていることが多い。游ゴシックに寄せるなら、**テーマ・マスター・レイアウト・全スライドの latin/ea/cs すべて**を置換する。スライド本文だけ直しても、プレースホルダ由来の文字が別フォントで残る。手順とコードは `pptx-house-style` の該当節にある。

フォント置換は**スライドXMLを書き出した後に毎回**流す（生成のたびに元フォントが復活するため）。

## はみ出し検査（必須）

テキストは自動改行で下へ伸び、フッターや次要素に重なる。目視だけでは漏れるので、書き出すたびに測る。各シェイプについて (1) 推定描画高さ ≤ ボックス高、(2) 最下端 < FOOT を確認する。全角=1em・半角=0.55em で行数を見積もり、行間倍率を掛けて高さを出す。1つでも FOOT を割ったら、その要素を上げるか本文を削る。目安として **フッターまで 0.5in（約457000 EMU）以上**空ける。`pptx-house-style/scripts/pptx_audit.py` が実装している。

## 表で埋まった資料を、図のある資料に組み直す

「情報が薄い」「デザインがダサい」という指摘の正体が、**図が1枚もないこと**である場合が多い。
表と箇条書きだけの資料は、どれだけ体裁を整えても平板に見える。上場企業のIR資料を実測すると、
テキスト主体のページでも必ず右か下に図が添えられている。

### 図にするか、表のままにするかの分け方

**表が正しいのは、項目と属性の対応が主題のとき**（監査の前提、指摘の一覧、比較の属性）。
**図にすべきなのは、次の5つ**。

| 内容 | 図の型 |
|---|---|
| 期間・量の大小そのものが主張 | 長さを実量に比例させた帯。比例させたことを注記する |
| 上下・内外の層の対比 | 同幅・同高のスタックを2つ。境界に一文 |
| 順序と時間経過 | 節点を等間隔に置き、線は水平のみ。上下に振り分ける |
| 2つの量が開いていく関係 | 2本の線とその間の面。関係の図であり実測値でない旨を注記 |
| 段階が上がっていく選択 | 右上がりの階段。段が上がるほど濃く |

**比例させるかどうかを毎回決め、注記に書く。** 期間や量を語る図は比例必須（グラフ扱い）。
層や役割分担の図は比例不要（図扱い）。この線引きを注記で明示すると、中立性の担保にもなる。

### 表を使わない比較

罫線が担っている仕事は「同じ属性を同じ高さに並べる」ことだけなので、
**位置を揃えれば罫線は要らない**。4つの選択肢を比べるなら、列を4つ立て、
左に属性名を右揃えで置き、属性の切れ目に極薄の横罫を引く。

さらに、**量を持つ属性（工数、期間、規模）は数字だけでなく帯にする。**
数字を読まなくても左から右へ増えることが分かる。帯の色は列の上辺の帯と同じ濃さにして、
色・位置・長さの3つが同じ方向を指すようにする。

**弱点を書く行だけ、文字をグレーに落とす。** 赤や記号を使わずに、
すべての選択肢に弱点があることを公平に示せる。中立的な情報提供の資料ではこれが効く。

### 図を描くときの実装方針

図形は pptx ネイティブのまま置き、**文字も pptx のテキストとして重ねる**。
SVG を画像として貼ると、図の中だけフォントが変わり、文字の選択も修正もできなくなる。
曲線が要る図（2本の線と間の面など）だけ、`a:custGeom` の `a:pathLst` で多角形を作る。
点を16分割程度で打てば、曲線に見える折れ線になる。

```python
# custGeom で多角形。塗りにも折れ線にも使える
pts = [(x, y), ...]                    # インチ
a = [(x, f(x)) for x in xs]            # 上の線
b = [(x, g(x)) for x in xs]            # 下の線
poly(slide, a + list(reversed(b)), fill=淡赤, line=None)   # 間の面
poly(slide, b, fill=None, line=グレー, close=False)         # 下の線
poly(slide, a, fill=None, line=主色,   close=False)         # 上の線
```

### 図の中に文を入れない

図の中は名詞句だけにして、文はすべて図の外に出す。
図が構造を示し、文字が理由を述べる、という分担にする。
図の要素に番号を振り、図の外のテキストの番号と色を一致させると、引き出し線が要らなくなる。

## 実測にもとづく型

上場企業のIR資料10社580ページと、note「パワポ研」58記事に載っている
実企業スライド約900枚を実際に見て確かめた型。迷ったらこの順に従う。

### 枠線を引かない

区画を四角い枠で仕切らない。**薄いグレーの地に白いカードを置く**か、色帯で分ける。
「枠線」を主題にした記事の9枚を見ても、四角い囲みで区画を作っている例はほぼない。
表も縦罫をゼロにして、横罫は極細のグレー、ヘッダ行だけベタ塗りにする。

どうしても箱が要るときは、**4辺のうち2辺だけ**を引く
（左＋上のL字、または左＋下。上辺はカテゴリの色帯で代替する）。

枠線を出すのは1枚に1〜2か所だけ。必ず「ここを見ろ」の意味を持たせる。
配色は、地が単色なら補色、地が多色なら既存色相の濃い側を使う。

### 強調は、塗りの反転か枠だけの二択

中間的な強調を作らない。4象限のうち自社の1つだけを濃いベタ＋白抜きにするか、
ファネル全体はグレーのまま自社範囲だけ太枠で囲むか、どちらかにする。

**太字ではなく、文字色を1色だけ変える。** 引用文の中で要点だけ色を変える型が、
コンサルティングファームの報告書に共通していた。

**対比するもう一方は、完全にグレースケールに落とす。**
従来の商流をグレー、自社が変える商流だけカラー、という置き方。
導入前と導入後を比べるページはすべてこれで組める。

### アクセント色は面積10%以下、線・文字・枠だけ

面には広げない。基調は1色相の濃淡4段で作り、階層は色相ではなく明度の段で表す。
色を増やさずに階層だけを増やせる。

地が白なら色は線・タグ・数値に置く。地が濃色なら白をボックスと文字に使う。
段階や成長を濃淡のグラデーションで示すときも、**濃い色は矢印と枠線に残す**と、
どれが主色なのかが伝わる。

### ピクトグラムは塗りの単色

線画ではなく、塗りの単色アイコンを使う。くり抜きは、地の色で塗った小さな図形を
重ねて表す。円の中に入れる形にすると、大きさが揃って並べやすい。
色はアクセント色1色に統一し、アイコンごとに色を変えない。

### 矢印は5つの用途だけ

「矢印」を主題にした記事の12枚に、**行頭の「→」も文中の「→」も1枚もなかった。**
矢印が出るのは次の5つだけ。

1. トレンドの背景に敷く極太の1本
2. フェーズの帯そのものを矢印形にする
3. 状態変化に文字を載せる
4. 循環の経路
5. 段と段の接続

線種の意味も揃える。**実線＝実績、点線＝将来・見込み。**

### 章扉に全体目次を置き、現在地を示す

章扉を主題にした記事の26枚のうち17枚がこの型だった。
現在地の示し方は6通り（他を薄くする／行を帯でハイライト／塗りを反転／
バッジの形を変える／下線／カードを塗る）。最も多いのは**他を薄くする**。

各章の開始ページ番号を併記する型もある（「P.02 / P.11 / P.22 / P.27」）。
本文ページにも上端にパンくずやタブを置いて現在地を示すと、通しで読める。

### 見出しは、カテゴリのタブ＋メッセージ

カテゴリは**ベタ塗りの角丸タブ**に入れる。区切り記号（│ ｜）より確実に伝わる。
見出しとリードの行頭には**細い縦バー**を置く。
2層を作るのは、区切り記号ではなく**文字サイズと太さの落差**。

### 「土台」を描くときの型

比喩を図にするときは、**図形の上に載るラベルをすべて名詞句にする。**
比喩を主題にした記事の11枚すべてがそうだった。文が入ってよいのは、
見出し・リード・図の外の説明ブロック・土台の直下の解説・吹き出しの5か所だけ。

土台は台形にして、中に名詞1語を大きく置き、その直下に説明文を1〜2行添える。
土台だけ色を変え（グレーの台形）、上に浮く要素は白い角丸ピルにする。
上下の因果は矢印を増やさず、**下から上へ細い縦線を1本ずつ**引く。

### 模式図には注記を付ける

「イメージ図であり正確性を保証するものではない」旨を必ず入れる。
競合比較なら「当社独自の見解に基づく」と書く。日本のIR資料では事実上の必須要件。

## 図を「絵」にする ── 足し算の側

このスキルはもともと引き算（色を減らす、線を消す、余白を取る）しか書いていなかった。
引き算だけで図を作ると、**色違いの箱が等間隔に並んだ図**になる。
実企業スライド約990枚を1枚ずつ見て測った、足し算の側を以下に置く。

### 主役は「大きさ」では作れない

実測すると、主役の数字は本文の 2.2〜2.5倍、脚注の 4〜4.5倍しかない。
ラバブルの「479」は軸ラベルのわずか1.46倍。**5倍のような差はどこにもない。**
主役を作っているのは次の4つで、大きさは補助にすぎない。

**1. 濃さ ── 脇役を全部「白地＋1px枠＋黒文字」に落とし、主役だけベタ塗り＋白抜きにする**

同じ形・同じ大きさのまま、塗りだけを変える。これが最頻出の型。
ヒットのファネルは14個の角丸ピルのうち13個が白地＋グレー枠で、
「屋外広告」の1個だけ濃紺ベタ＋白抜き。大きさは幅が15%広いだけ。

逆パターンもある。トヨタの神殿図は屋根も柱も基壇も**すべてグレー**で描き、
強調したい基壇だけ赤の点線枠＋赤文字。**全部グレーにしてから1か所だけ色を戻す。**

**2. 孤立 ── 脇役を密集させ、主役の周りだけ余白を10倍取る**

Liberawareのマトリクスの実測。競合19社のピルは縦の隙間10px、横15pxでぎっしり。
自社カードの左隣までは103px。**脇役同士10px、主役の周り100px。**
面積比も19倍あるが、目を引いているのは面積ではなく余白のほう。

**等間隔に整えることが、そのままフラット化になる。** 意図的に密度を偏らせる。

**3. 形 ── 主役だけ形を変える**

| 手 | 具体 |
|---|---|
| 正円に入れて右上に置く | 直径がスライド幅の12%の色ベタ円。中に3行（年→項目名→数値）。見出し帯に半分乗り上げる |
| 円バッジを帯の端に食い込ませる | 白地＋4px色枠の正円を、矢羽根の角に跨がせる。中は「1st」大＋「STEP」小 |
| 枠だけ描いて重ねる | グレーの図の上に、注力範囲だけ太いアウトラインを重ねる。塗らない |
| 主役の象限だけ床を塗る | マトリクスで、自社の象限の面だけ淡い色で塗る |

**4. 重なり ── 要素を重ねて前後関係を作る**

円バッジをカードの左辺に半分だけかぶせる（器の外に4割はみ出す）。
タブを帯の境界に食い込ませる。写真の上に白い角丸カードを浮かせる。
**等間隔かつ非重複だと、全要素が同一レイヤーに見える。** 重なりが1か所あるだけで奥行きが出る。

### 1ページに1つ、大きな形を置く

良い図には「意味を持った1つの大きな形」がある。灯台、瓶、木、神殿、巨大な曲線矢印。
**その形が版面の幅の40〜60%を占める。** 箱の集合ではない。

抽象図形を、その事業の実物に置き換えられないかを先に考える。
棒グラフを缶にする、階段を封筒にする、カードの色をビールの泡と液体にする。

### ピクトグラムの作り方

**型は3つしかない。1つの資料の中では1型に統一する。**

| 型 | 使う場面 | 作り |
|---|---|---|
| モノライン | 白地・淡色地の資料 | 線だけ。塗りなし。端は丸、角も丸 |
| ベタ塗りシルエット | 濃色地の資料 | 白100%の面で描く。線という概念がない |
| 技術線画 | 自社製品を見せるとき | 実物の輪郭を1.5pxだけで描き、大きく拡大して端で切る |

**線幅 ＝ 外形サイズ ÷ 14。** 本文の縦棒の2.5〜3倍、太字見出しと同じ太さの階級に置く。
82pxの絵に5.8pxの線。細い線で描くと「あとから貼った素材」に見える。

**1つのアイコンに使う色は1色。例外なし。** 2色目が出るのは「線は黒、塗りは緑」と役割で分けたときだけ。

**器に入れるのは、主役1個か、同格が3〜6個並ぶときだけ。** 説明用の小さいアイコンは器に入れない。
入れるときは **アイコン＝円の55%**。器の色は3通り。
①ブランド色のベタ（中身は白）②ブランド色の10〜15%ティント（中身はブランド色の線）③白（中身はブランド色の線）。

**単純化の作法**

1. 持ち物1個で職種・機能を言う。人に服も表情も描かない
2. 中身を描かず、輪郭と識別子1個で済ませる（書類＝右上の折れ角＋横線2本、雲＝半円3つ）
3. **新しい絵を描かず、既存の絵を2つ重ねる。** 円＋斜めの柄＝虫めがね。虫めがね＋折れ線＝分析
4. 同じスライドの中では、絵の線の本数を揃える（7〜12本に収める）

**具体物の描き方**

| 物 | 描き方 |
|---|---|
| 人 | 丸い頭＋台形の肩。腕も脚も描かない。頭と肩は接する |
| 建物 | 長方形＋等間隔の小さい正方形の窓。屋根は描かない |
| 書類 | 長方形の右上角だけ折る。中身は横線2〜3本 |
| データベース | 円柱。上に楕円1つ＋側面に横線2本まで |
| 雲 | 半円を3〜4個つないだ輪郭1本 |
| 歯車 | 円＋台形の歯を6〜8個。中心の穴は必ず開ける |
| 虫めがね | 円＋45°の柄。柄は円の縁から生やす。円の中に調べる対象を入れる |
| 盾 | 上辺が直線、下がV字に尖る5角形。中にチェック1個 |
| 鍵 | 半円のシャックル＋角丸四角の本体。鍵穴は丸1つ |
| グラフ | 棒3本（低・中・高）だけ。目盛も軸も描かない |
| 目 | 横長の輪＋中に瞳。まつげは描かない |

**並べ方**：外形の正方形を揃える。間隔はアイコン1個分。ラベルとの距離はアイコン高さの25〜30%。
ラベルの行数が違っても、アイコンの上端は必ず揃える。

### 装飾のパーツ

- **角丸は2択**。大きな面は高さの3〜5%、小さいタグは15%か完全なピル（50%）。中間を作らない
- **透かしの明度差も2択**。読ませない地紋は4〜10%、読ませる巨大数字は35〜50%。15〜30%は実物に1枚もない
- **円バッジ**：番号や段階を、正円に2段（大きい数字＋小さい語）で入れる
- **番号タグ**：角丸正方形（r＝辺の15%）に白の数字。図の上に置き、図の外のカードと対応させる
- **影は使うか、地の色を敷くか、どちらか一方だけ**。両方やると濁る。影を使うなら不透明度10%以下

### 情報の階層は4段にする

見出し ／ 言い切りのリード1行 ／ 図 ／ 脚注。
1280×720に正規化すると 34 / 22 / 17 / 9 px。
**箱を並べただけの図は第3段しか持っていない。** だからフラットに見える。

### SVGで絵を起こして貼る

PowerPointの図形の組み合わせでは、モノラインのピクトグラムも立体も作れない。
絵の部分はSVGで書き、高解像度のPNGに変換して図として貼る。文字は pptx のネイティブのまま置く。

```
SVG（stroke-linecap="round" stroke-linejoin="round"、stroke-width = size/14、色は1色）
  → cairosvg で 4倍解像度のPNGへ
  → add_picture で配置
```

絵と文字を分けることで、絵の質を上げながら、文字は選択でき、フォントも本文と揃う。

## 現在地の示し方

IR資料10社の本文205ページを実読して数えた。**思いつきで置かない。母数の中にある型だけを使う。**

| 状態 | ページ数 | 割合 |
|---|---|---|
| 章レベルの現在地が分かる | 225 | 51.0% |
| 上位ラベルはあるが章は分からない | 113 | 25.6% |
| 何もない | 103 | 23.4% |

**会社間で二極化する。** sansan・mercari・UNITED ARROWS が100%、arent・euglena・マネーフォワード・グッドパッチが0%。
グッドパッチは81ページ全部で何も置いていない。ページ数とも資料の種類とも相関しない。

### 使ってよい型（母数にあるもの）

| 型 | 作り | 実例 |
|---|---|---|
| **パンくず**（最多） | 見出しの上に「第5章　章名」を1行、小さいグレーで | sansan、コンサル報告書16/22 |
| 左上タブ | ページ左上に章のタブを横に並べ、現在地だけ濃色 | dive（本文の96%） |
| 章番号の四角 | 見出しの左に章番号を小さい四角で | mercari（100%） |
| 章扉で目次を再掲 | 章扉に全体目次を置き、現在地だけ濃く | 章扉26枚中15枚（58%） |
| 置かない | 章扉だけで区切る | グッドパッチほか23.4% |

### 使ってはいけない形

**右上に縦積みのインジケータを置かない。** IR資料10社580ページに1例もない。
10社の右上はロゴ4社／資料名とページ番号1社／ページ番号1社／空白4社で、現在地インジケータは0社。

母数に出た縦積み・横並びのインジケータは**すべて3〜4項目**で、6項目の例はゼロ。
**番号だけを置いて項目名を書かない例もゼロ。** 番号だけでは何を指しているか読み手に分からない。

## 仕上げの点検

- 色ベタ塗りカード・装飾ストライプ・矢印・原色の差し色が残っていないか
- 差し色は1枚1色に収まっているか
- 全要素が同じ大きさで並んでいないか（フラット化）。主役が一番大きいか
- フッター・ロゴ・ページ番号（テンプレート由来）を潰していないか
- `<placeholder>` や `×××` などの仮テキストが残っていないか
- pptx skill の validate と、はみ出し検査を両方通したか

## やらないこと

- python-pptx でテキストボックスを積む（高さ計算が破綻しやすい）
- マスター・レイアウトを自作する（テンプレートを継承する）
- 差し色でスライドを賑やかすこと自体を目的化する
- 検査を飛ばして納品する

## 適用外

図（フローチャート等）単体、文章のみの成果物、Word/Excel、テンプレートを持たないゼロからのブランド設計。
