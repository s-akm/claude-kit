# Deck Visual Design（落ち着いた企業スライド）

pptx skill と併用する。pptx skill が「ファイルをどう組むか」を担い、こちらは「どう見せるか」を担う。テンプレートのマスター・レイアウト・フッターは必ず継承し、その上に本文を載せる。

顧客の既存デッキに合わせる作業は `pptx-house-style` を使う。**既存ページが1枚でもあるなら、このスキルの数値ではなく実測値を優先する。** こちらは参照できる既存ページが無いときの初期値である。

## AIが作るスライドがダサくなる理由

避けるべきものを名指しする。生成物にこれらが出たら作り直す。

- **色ベタ塗りのカード**を何枚も並べる（濃い青地に白抜き文字のブロックが3つ横並び、など）
- **装飾ストライプ**、見出し脇の色帯、意味のない図形
- **矢印記号（→ ▶ ⇒）** を本文に直置きし、しかも原色で目立たせる
- **アクセントカラーの多用**。1枚に3色も4色も差し色が入る
- **過剰な太字**。文章全体が太字だと強弱が消える
- **中身のない角丸ボックス**の乱用
- 全項目が同じ大きさ・同じ色で並ぶ**フラットな一覧**

良いスライドは、白地・広い余白・細い罫線・1〜2色の抑えた差し色でできている。情報の階層は、色数ではなく**文字サイズと余白**で作る。

## デザイントークン

16:9（13.333in × 7.5in = 12192000 × 6858000 EMU）を前提とする。

```
# 色（テンプレートの基調に合わせて BASE を差し替える。他はほぼ共通で使える）
BASE = "0B3B70"   # 基調色。見出し・数字・罫線の強い方。テンプレートのブランド色に合わせる
INK  = "1A1A1A"   # 本文。真っ黒(000000)にしない
SUB  = "6B7280"   # 補足・二次情報のグレー
LINE = "DCE3EA"   # 細い罫線。うっすら見える程度
WASH = "F4F7FA"   # 淡いパネル地。ベタ塗りの代わりにこれを使う
SRC  = "9AA5B1"   # 出典・注記のさらに薄いグレー
ACC  = "0A7EA4"   # 差し色。青緑寄りにして「デフォルト青」を避ける。1枚に1色まで
WARN = "B3541E"   # 「大／注意」を示す時だけのくすんだテラコッタ

# 余白（本文領域）
CX, CY, CW = 719983, 1080838, 10752052   # 左端・上端(タイトル下)・本文幅
FOOT = 6426100                            # フッター上端。本文はここより上で終える

FONT = "游ゴシック"   # 日本語資料は原則これで全系統統一（後述）
```

配色の原則：**基調色＋グレー階調（INK/SUB/SRC/LINE/WASH）が土台。差し色（ACC/WARN）は1枚に1色、1〜2箇所まで。** 差し色を「なんとなく賑やかしで」使わない。強調の意味があるときだけ。

## 文字サイズの段階

サイズで階層を作る。太字とグレーを併用して、色に頼らない。

```
大きな数字・キーメッセージ   2800–3000 (b)
スライド内の小見出し         1900–2000 (b, BASE)
項目タイトル                 1400–1550 (b, INK/BASE)
リード（タイトル下の一文）    1250      (SUB)
本文                         1100–1200 (INK)
補足・キャプション            1000–1100 (SUB)
出典・注記                    850–950   (SRC)
```

## レイアウトの型（この4つで大半が組める）

1. **リード＋3カラム**：タイトル下に主張を1文（リード）。下に3つの観点を、番号＋細罫線＋見出し＋本文で。カードのベタ塗りはしない。区切りは罫線と余白で作る。
2. **数字ブロック**：4つ以下の指標を横並び。各々「細い縦アクセント罫線＋大きな数字＋ラベル＋補足＋薄い出典」。数字を主役にする。
3. **比較テーブル**：ヘッダ行だけ基調色地に白文字。データ行は白と WASH の交互（ゼブラ）。枠線は LINE。強調したい値だけ色と太字。
4. **淡色インセット**：結論・帰結・注意を、WASH 地の囲みにグレー文字で置く。矢印もアクセント色も使わない。「囲ってあること」自体が弱い強調になる。

## 実装：XMLを直接組む

python-pptx はテキストボックスの自動高さやフォント指定で扱いづらい。テンプレートを unzip し、スライド XML を文字列生成して差し込むのが確実。罫線・淡背景・セル書式・フォント統一のヘルパは `pptx-house-style/scripts/deckkit.py` にある。要点は次のとおり。

- テキストボックス、塗り／枠付き図形、罫線、プレースホルダ見出し、リード文、出典注記の6種類でほぼ足りる
- 各段落は行間を明示する（例 140000 = 140%）
- 色は必ずトークンを使い、直値を散らさない

## フォント統一（日本語）

テンプレートは英数と日本語で別フォントが当たっていることが多い。游ゴシックに寄せるなら、**テーマ・マスター・レイアウト・全スライドの latin/ea/cs すべて**を置換する。スライド本文だけ直しても、プレースホルダ由来の文字が別フォントで残る。手順とコードは `pptx-house-style` の該当節にある。

フォント置換は**スライドXMLを書き出した後に毎回**流す（生成のたびに元フォントが復活するため）。

## はみ出し検査（必須）

テキストは自動改行で下へ伸び、フッターや次要素に重なる。目視だけでは漏れるので、書き出すたびに測る。各シェイプについて (1) 推定描画高さ ≤ ボックス高、(2) 最下端 < FOOT を確認する。全角=1em・半角=0.55em で行数を見積もり、行間倍率を掛けて高さを出す。1つでも FOOT を割ったら、その要素を上げるか本文を削る。目安として **フッターまで 0.5in（約457000 EMU）以上**空ける。`pptx-house-style/scripts/pptx_audit.py` が実装している。

## 仕上げの点検

- 色ベタ塗りカード・装飾ストライプ・矢印・原色の差し色が残っていないか
- 差し色は1枚1色に収まっているか
- 全要素が同じ大きさで並んでいないか（フラット化）。主役が一番大きいか
- フッター・ロゴ・ページ番号（テンプレート由来）を潰していないか
- `<placeholder>` や `×××` などの仮テキストが残っていないか
- pptx skill の validate と、はみ出し検査を両方通したか

## やらないこと

- python-pptx でテキストボックスを積む（高さ計算が破綻しやすい）
- マスター・レイアウトを自作する（テンプレートを継承する）
- 差し色でスライドを賑やかすこと自体を目的化する
- 検査を飛ばして納品する

## 適用外

図（フローチャート等）単体、文章のみの成果物、Word/Excel、テンプレートを持たないゼロからのブランド設計。
