# 見出し・リード文・注記・表の構成

文体を整える前に、資料の骨格を整える。ここに挙げたものは、いずれもこれまでのプロジェクトで「言い回し」ではなく「構成」として指摘を受けた点である。

## 1. 見出しは体言止めで短く。「の」を重ねない

| 直す前 | 直したあと |
|---|---|
| 現行の資料と新システムの資料をどうつなぐか | 機能要件各資料の参照方式 |
| 現行の機能をどの資料から並べているか | 現行機能をどの資料から参照しているか |
| 現行にはなく、新システムで加わるもの | 現行に存在しない追加機能 |
| 2. 資料の読み方 | 2. 確認方法 |

削れる「の」は削る。目次の一行説明も同じ扱いで、体言止めで短く書く。

## 2. 見出しに接続詞を置かない

「ただし〜」「一方で〜」「なお〜」で始まる見出しは、直前の見出しに寄生していて単独では読めない。スライドや長い資料の見出しは飛ばし読みされる。

| 直す前 | 直したあと |
|---|---|
| ただし編集はできません | 古い記事はCMSからは修正できません |
| 一方で工数は増えます | 工数は1.5倍になります |
| なお件数は未確定です | 件数はまだ数えられていません |

## 3. 見出しに範囲を隅付き括弧で示す

同じ対象を別の面から扱う表が並ぶときは、見出しの先頭で範囲を示す。「〜の」でつながない。

| 直す前 | 直したあと |
|---|---|
| ニュース　対応表 | 【管理画面】ニュース　対応表 |
| 公開サイトのニュース　対応表 | 【公開サイト】ニュース　対応表 |

本文で言うときは「ニュース管理画面」のように名詞を続ける。

## 4. 中身のないリード文を置かない

タイトル下の一文は、埋めるために書かない。書くことがなければ空けておく。

落とした例。「ニュース検索・一覧 1.1 です。」「マニュアル 4.2.2 の続きです。」「ニュース詳細 2.1 の続きです。」いずれも、見出しに書いてあることを繰り返しているだけで情報が増えていない。

分割した表の2枚目以降にはリード文を置かない。1枚目だけ、読み方の説明を1文入れる。2枚目以降はタイトルの (2/3) だけで足りる。

## 5. 補足は本文に混ぜず、表の下に置く

細かい注記を申し送り事項に格上げしない。対応表の下に ※ で1行添える。

例：基本設計書でニュース詳細の機能番号が 2.1 と 1.2 に割れている件は、申し送り事項ではなく対応表下部の注記にした。読み手が判断を求められる話ではないため。

判断の目安は「相手に何かを決めてもらう必要があるか」。あるなら申し送り事項、ないなら注記。

## 6. 出典欄には出典だけを書く

出典・注記の行に、約束事や次のアクションを混ぜない。読み手は出典欄を飛ばすので、大事な約束がそこにあると伝わらない。

```
悪い： （出典）件数は公開ページの実測、閲覧の割合はGA4の分析に基づきます。
        前回の30〜50人日が何本を想定していたかも、あらためてお示しします。
良い： （出典）件数は公開ページの実測、閲覧の割合はGA4の分析に基づきます。
        工数は現時点の概算で、計画の作成時に確定します。
      → 約束事は本文か注記の行へ移す
```

## 7. 分類の列を惜しまない

行が増えると、その行がどの機能のどこの話か分からなくなる。抜き出した表には「機能」「区分」の列を先頭に置く。

例：新規追加機能と申し送り事項の表に、機能（ニュース）と区分（管理画面・公開サイト）の2列を追加した。列が2つ増えても、行の意味が分かるほうが読める。

## 8. 申し送り事項は根拠を示せるものだけ書く

推測で「決まっていない」と書かない。**資料のどこに未確定と書いてあるかを言えるものだけ残す。**

過去に落とした例と、その理由。

| 落とした項目 | 理由 |
|---|---|
| 承認依頼のメール通知 | 現行と新システムで差分がなかった |
| 加入船検索の reCAPTCHA | 対象範囲に含まれていなかった |
| 会員限定記事の遷移先 | 画面要件 P.31 に記載があった |
| 宛名と署名の定型文 | CMSのカスタムフィールドで実現できることを確認した |
| ロスプリベンションニュースの受け皿 | ニュース一覧に含まれる前提と確認した |
| 記事ページの2類型化 | 決定事項だった |

書く前に、資料と議事録の両方を当たる。当たった結果「書いてある」なら落とす。「書いていない」なら残す。

同じ根拠（同じ項番）から出る論点は、入力側と表示側に分けず1件にまとめる。件数を増やすと、相手が確認する手間だけが増える。

## 9. 決定済みか未決かを一件ずつ判別する

決定済みの項目を「案です」「ご意向をうかがったうえで」と書くと未決に見える。逆に未決を断定すると後で覆せない。

判別できたら、決定済みは申し送り事項から外し、対応表の区分だけで示す。※ も外す。

例：ニュース記事を実務通知型と読み物・告知型に分ける件は決定事項だったため、申し送り事項から削除し、対応表の ※ も外した。

## 10. レイアウトの確認（スライド・表）

文字数と枠幅の関係は、書いた後ではなく書く前に見積もる。

- 見出しの文字数が枠幅を超えると折り返す。13.5pt なら全角1文字あたり約 0.19in。枠幅から逆算して文字数を決める
- 表のセルは、値に付く記号（※ など）の分の幅を最初から見込む。区分列は 0.70in では「変更あり ※」が改行するため 1.05in にした
- 淡背景のボックスは、中の文章より高さを 0.15in 以上大きく取る
- 本文の左端と幅は、資料全体で1つの値に揃える

**枠幅を広げるより、見出しの語を削るほうが体裁が保たれる。** 詳細は `pptx-house-style` スキルを参照。
