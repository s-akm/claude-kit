# 20_design — 基本設計

## 何を置くか

| ファイル | 内容 |
|---|---|
| `basic-design.md` | 基本設計 |
| `review-記録.md` | 基本設計レビューの記録 |

画面、API、データ、権限、エラー処理、性能、可用性、監視、バックアップ、運用・保守を扱う。

## 扱い

| 項目 | 値 |
|---|---|
| 種別 | 正本 |
| Git 管理 | 対象 |
| 顧客情報・認証情報 | 不可（接続先はホスト名ではなく役割名で記載） |
| Claude に読ませる | 可 |
| Claude に書かせる | 可（レビュー後にコミット） |

## 書き方の約束

- どの要件 ID に対応する設計かを各節に書く。対応がない設計は、要件の漏れか、設計の作りすぎのどちらか
- 未決を確定事項として書かない。決まっていないところは「未決（`OI-nn`）」と書いて `10_requirements/open-items.md` へ紐づける
- 数値（件数、サイズ、秒数）を書いたら、その根拠も 1 行書く
