# チェック結果

`just qa` が出力する結果の読み方。コマンド自体は [README のコマンドリファレンス](../README.md#コマンドリファレンス) にある。

## Exit code

| 値 | 意味 | 次のアクション |
|---|---|---|
| 0 | 指摘なし | 目視確認へ進む |
| 1 | 警告あり | 内容を読み、修正か誤検知かを判断する |
| 2 | 提出不可の指摘あり | 修正してから提出する |

`2` になるのは次のいずれか。

- Excel の数式エラー、外部リンク、壊れた名前定義
- PDF で全ページの文字が抽出できない
- ファイルが読めない

## 出力ファイル

```text
90_qa/2026-09-01-1122/
├── summary.md              まとめ。ここから読む
├── text.md / text.json     日本語と Markdown
├── xlsx-NAME.md / .json    Excel
├── pptx-NAME.md / .json    PowerPoint
├── pdf-NAME.md / .json     PDF
├── slides/page-*.jpg       全ページの画像
└── contact.jpg             contact sheet
```

各 JSON の先頭に、実行日時、対象ファイルのパスと SHA-256、使用ツールのバージョンが入る。
どのバージョンのファイルをいつ何でチェックしたかを、あとから追える。

指摘は 3 段階。要確認は提出前に修正する。警告は確認が要る。情報は参考で、判断は人がする。

## チェック対象外の項目

各 Markdown の冒頭に、そのチェックで判定していないことを出力する。

- 計算結果が保存されていない Excel での 0 除算などの実行時エラー
- グラフと元データの値が合っているか
- Excel の数値とスライドの数値が一致しているか
- 出典が要るスライドかどうか
- 結論と本文が食い違っていないか

`summary.md` にも同じものが並ぶ。ここは目視で確認する。

## 誤検知の扱い

結果ファイルは編集しない。

| 状況 | 対応 |
|---|---|
| その 1 件だけ | `50_tracking/qa-record.md` に、問題ないと判断した理由を 1 行書く |
| 特定ファイル全体 | ファイル先頭に `<!-- textlint-disable RULE -->` を書く |
| プロジェクト全体で繰り返す | `.textlintrc.json` か `prh/project-terms.yml` を修正し、理由をコミットメッセージに書く |

誤検知とだけ書き残さない。理由を残せば、次の版で同じ判断を繰り返さずに済む。
