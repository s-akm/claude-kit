# チェック結果

`just qa` が出力する結果の読み方。コマンドは [README のコマンドリファレンス](../README.md#コマンドリファレンス) を参照。

## Exit code

| 値 | 意味 | 対象 | 対応 |
|---|---|---|---|
| 0 | 指摘なし | — | 目視確認へ |
| 1 | 警告あり | 非表示要素、名前定義、表示形式の揺れ、文字切れ、フォント混在、タイトル重複ほか | 内容を確認し、修正か誤検知かを判断 |
| 2 | 提出不可の指摘あり | Excel の数式エラー・外部リンク・壊れた名前定義、PDF の全ページで文字抽出不可、ファイル読み込み不可 | 修正後に提出 |

## 出力ファイル

```text
90_qa/2026-09-01-1122/
├── summary.md              全体
├── text.md / text.json     日本語と Markdown
├── xlsx-NAME.md / .json    Excel
├── pptx-NAME.md / .json    PowerPoint
├── pdf-NAME.md / .json     PDF
├── slides/page-*.jpg       全ページの画像
└── contact.jpg             contact sheet
```

各 JSON の先頭に、実行日時、対象ファイルのパスと SHA-256、使用ツールのバージョンを記録。
どのバージョンのファイルをいつ何でチェックしたかが追跡可能。

指摘の重要度は 3 段階。要確認は提出前に修正、警告は要確認、情報は参考。判断は利用者。

## チェック対象外の項目

各 Markdown の冒頭と `summary.md` に、そのチェックで判定していない項目を出力。いずれも目視で確認。

- 計算結果が保存されていない Excel での 0 除算などの実行時エラー
- グラフと元データの値の一致
- Excel の数値とスライドの数値の一致
- 出典の要否
- 結論と本文の整合

## 誤検知の扱い

結果ファイルの編集は不可。

| 範囲 | 対応 |
|---|---|
| 1 件のみ | `50_tracking/qa-record.md` に、問題なしと判断した理由を 1 行記載 |
| ファイル単位 | 対象ファイルの先頭に `<!-- textlint-disable RULE -->` を記載 |
| プロジェクト全体 | `.textlintrc.json` か `prh/project-terms.yml` を修正し、理由をコミットメッセージに記載 |

理由を残さず誤検知とだけ記録すると、次の版で同じ判断を繰り返すことになる。
