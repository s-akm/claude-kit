# チェック結果

`just qa` が出力する結果の読み方。コマンドは [README のコマンドリファレンス](../README.md#コマンドリファレンス) にある。

## Exit code

| 値 | 意味 | 対象 | 対応 |
|---|---|---|---|
| 0 | 指摘なし | — | 目視確認へ進む |
| 1 | 警告あり | 非表示要素、名前定義、表示形式の揺れ、文字切れ、フォント混在、タイトル重複ほか | 内容を読み、修正か誤検知かを判断する |
| 2 | 提出不可の指摘あり | Excel の数式エラー・外部リンク・壊れた名前定義、PDF の全ページで文字が抽出できない、ファイルが読めない | 修正してから提出する |

## 出力ファイル

```text
90_qa/2026-09-01-1122/
├── summary.md              全体
├── text.md / text.json     日本語と Markdown
├── xlsx-NAME.md / .json    Excel
├── pptx-NAME.md / .json    PowerPoint
├── pdf-NAME.md / .json     PDF
├── slides/page-*.jpg       全ページの画像
└── contact.jpg             contact sheet
```

各 JSON の先頭に、実行日時、対象ファイルのパスと SHA-256、使用ツールのバージョンが入る。
どのバージョンのファイルをいつ何でチェックしたかが追跡可能になる。

指摘の重要度は 3 段階。要確認は提出前に修正する。警告は確認が要る。情報は参考で、判断は利用者が行う。

## チェック対象外の項目

各 Markdown の冒頭と `summary.md` に、そのチェックで判定していない項目を出力する。
いずれも目視で確認する。

- 計算結果が保存されていない Excel での 0 除算などの実行時エラー
- グラフと元データの値の一致
- Excel の数値とスライドの数値の一致
- 出典の要否
- 結論と本文の整合

## 誤検知の扱い

結果ファイルは編集しない。

| 範囲 | 対応 |
|---|---|
| 1 件のみ | `50_tracking/qa-record.md` に、問題ないと判断した理由を 1 行書く |
| ファイル単位 | 対象ファイルの先頭に `<!-- textlint-disable RULE -->` を書く |
| プロジェクト全体 | `.textlintrc.json` か `prh/project-terms.yml` を修正し、理由をコミットメッセージに書く |

理由を残さずに誤検知とだけ書くと、次の版で同じ判断を繰り返すことになる。
