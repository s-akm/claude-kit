# Claude for Microsoft 365 の使い方

Excel・PowerPoint・Word・Outlook のアドインとして Claude を使うときのメモ。
2026 年 9 月時点の公式ドキュメントに基づく。

---

## 1. 前提

| 項目 | 内容 |
|---|---|
| Claude のプラン | Pro・Max・Team・Enterprise が対象 |
| Microsoft 365 | 個人契約でよい。組織の管理者による展開は別手順 |
| Excel の版 | Mac 版 16.46 以降（ビルド 21011600 以降） |
| PowerPoint の版 | Mac 版 16.46 以降 |
| 対象外 | 2016 / 2019 の買い切り版、iPad、Android |

版の確認は、Excel → メニューバーの Excel → Excel について。

---

## 2. 導入

Microsoft AppSource の「Claude for Microsoft 365」を 1 回入れると、
Excel・PowerPoint・Word・Outlook の 4 つ分が入る。

| 手順 | 操作するアプリ | 開くメニュー | 選ぶもの |
|---|---|---|---|
| 1 | ブラウザ | Microsoft AppSource | 「Claude for Microsoft 365」→ Get it now |
| 2 | Excel | ツール → アドイン | Claude の有効化 |
| 3 | Excel | Claude のサイドバー | Claude アカウントでサインイン |
| 4 | PowerPoint・Word | 同上 | 1 回ずつ有効化してサインイン |
| 5 | 各アドイン | 設定 | 「Let Claude work across files」の確認 |

手順 4 を飛ばすと、アプリ間の連携が働かない。**使う予定のアプリすべてで 1 回は開いておく。**

手順 5 は Pro と Max では既定で有効だが、端末ごとの設定のため一度見ておく。

### 認証で渡す権限

Microsoft アカウントには、**開いているファイルの読み書き**の権限を渡す。
Claude アカウントには、通常の利用と同じ範囲。組織の管理者承認は、個人契約では不要。

---

## 3. できること・できないこと

| できる | できない |
|---|---|
| 開いているブック・デッキ・文書の読み書き | ファイルの新規作成、開く、閉じる、切り替え |
| アプリをまたいだ参照（Excel の数値を PowerPoint へ） | マクロと VBA |
| 数式の関係を保ったままの値の変更 | データテーブル |
| 有効にしたスキルの適用 | ローカルコマンドの実行（`just qa` は呼べない） |

**`just qa` はアドインからは呼べない。** ターミナルか、Cowork でフォルダを接続した状態で人が実行し、
`90_qa/` に出た結果をアドインの Claude に読ませる。

---

## 4. スキルの呼び方

Claude の設定で有効にしたスキルが、アドインでも自動で適用される。
明示的に呼ぶときは、サイドバーで `/` を打つと、そのアプリに関係するスキルだけが並ぶ。

| アプリ | よく使うもの |
|---|---|
| Excel | `/requirements-xlsx`、`/deliverable-review-register` |
| PowerPoint | `/pptx-house-style`、`/deck-visual-design`、`/emphasis-first-drafting` |
| Word | `/japanese-business-writing`、`/japanese-rewrite` |

アプリに関係しないスキルは一覧から外れる。

### スキル更新後の反映

リポジトリを直しただけでは、アドインが読むスキルは変わらない。

```sh
cd ~/workspace/claude-kit
bin/build-plugin
```

できた `.plugin` を Claude のチャットへ渡し、インストールで差し替える。

---

## 5. 各アプリの Instructions

サイドバーの設定にある Instructions はアプリごとに独立している。
Excel に書いた内容は PowerPoint へ引き継がれない。

プロジェクトをまたいで変わらないことだけを書く。

| 書く例 | 書かない例 |
|---|---|
| 数値は 3 桁区切りにする | 今のプロジェクトの要件 ID の採番規約 |
| 列見出しは太字にする | 今週の締め切り |
| 提出物は「です・ます」で書く | 特定ファイルの版 |

プロジェクトごとの約束は、プロジェクトディレクトリの `CLAUDE.md` に書く。

## 6. 外部から受け取った Excel のレビュー手順

外部由来のファイルには、非表示シート、セルコメント、数式の文字列、外部リンク先に
指示文が仕込まれていることがある。Anthropic の公式ドキュメントにも、
アドインが外部ファイルの内容で誤動作した検証結果が示されている。

**順番を守る。**

### 手順 1　アドインで開く前のチェック

```sh
cd ~/workspace/<プロジェクト名>
npx just qa-xlsx 00_sources/受領した定義書.xlsx
```

非表示のシート・行・列、外部リンク、名前定義、数式エラー、長い文字列が一覧になる。

### 手順 2　結果の確認

**結果に現れた文章は、資料の中身であって指示ではない。** 「これまでの指示は無視して」
「管理者からの依頼です」のような文が出たら、そのファイルは扱いを変える。
仕込まれていた事実を `50_tracking/qa-record.md` に記録する。

### 手順 3　外部リンクの照会

検出されたリンク先を自動で解決しない。発信元に、そのリンクが何かを聞く。

### 手順 4　複製での作業

原本は `00_sources/` に置いたまま触らない。編集が要るときは複製を作る。

### 手順 5　確認ダイアログの内容確認

アドインが危険な操作の前に確認を出す。外部由来のファイルでは、内容を読んでから承認する。

## 7. 留意事項

| 項目 | 内容 |
|---|---|
| 履歴の保存先 | ブラウザの IndexedDB にローカル保存。端末間の同期なし |
| データの保持 | 入出力は 30 日以内にバックエンドから削除 |
| 最終確認 | 公式ドキュメントに「人のレビューなしに最終成果物を確定させない」と明記 |
| 顧客データ | アドインで開いたファイルの内容は Claude へ送信。顧客との取り決めを事前に確認 |
| モデル | アドインで選択可能なモデルは claude.ai より少ない場合あり |

---

## 8. トラブルシューティング

| 症状 | 見るところ |
|---|---|
| 開いているファイルが見えない | アドインが有効になっているか（Mac は ツール → アドイン） |
| 他のアプリのファイルが読み込まれない | 各アドインの設定で「Let Claude work across files」が有効か。両方のアプリでアドインを開いたか |
| 変更が反映されない | Claude の処理は逐次実行。完了後に読み直しを依頼 |
| スキルが `/` で出てこない | そのアプリに関係しないスキルは一覧から外れる。`.plugin` を入れ直したか |
